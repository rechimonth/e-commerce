# AWS S3 Image Upload & Display Debug Plan

## Objective
Diagnose why product images uploaded to AWS S3 are not appearing in the deployed Vercel application, and resolve all configuration/code issues.

## Current State Analysis

### Deployed Site Status
- URL: `https://e-commerce-mauve-one-98.vercel.app/`
- **Critical finding:** The deployed site serves the root `index.html` (Vite dev entry point) instead of `dist/index.html` (production build). The root `index.html` references `/src/main.tsx` which does not exist in Vercel deployments. Result: empty page with only `<div id="root"></div>`, no JavaScript loads.
- Root `index.html` has `<script type="module" src="/src/main.tsx"></script>` — dev server only
- `dist/index.html` has `<script type="module" crossorigin src="/assets/index-D39lVrCI.js"></script>` — correct production bundle

### Upload Flow
1. Admin selects image in `ImageUploader` → `useUpload` hook → `uploadService.uploadFile()`
2. Frontend calls `POST /api/upload` with Firebase ID token, file metadata
3. Backend (`api/upload.ts`) validates admin role, generates presigned PUT URL via AWS SDK v3
4. Frontend uploads file directly to S3 via `PUT` to presigned URL
5. Backend returns `publicUrl` = `https://${bucket}.s3.${region}.amazonaws.com/${key}`
6. Frontend saves `publicUrl` + `key` to Firestore product document
7. UI renders `<img src={product.image.url} />`

### Identified Issues

| # | Issue | Severity | Root Cause |
|---|-------|----------|-----------|
| 1 | **Vercel serving wrong index.html** | CRITICAL | `vercel.json` rewrite `/"/(.*)"` → `"/index.html"` matches root `index.html` instead of `dist/index.html`. No JS bundle loads. |
| 2 | **S3 CORS not configured** | CRITICAL | User's CORS config looks correct now, but needs verification that PUT requests succeed. |
| 3 | **S3 objects not publicly readable** | CRITICAL | `publicUrl` assumes public read access. If bucket has "Block Public Access" enabled (AWS default), images return 403. |
| 4 | **No ACL on uploaded objects** | MEDIUM | `PutObjectCommand` didn't set `ACL: 'public-read'`. Code fix applied in previous step. |
| 5 | **Missing `ALLOWED_ORIGINS` env var** | HIGH | `/api/upload` CORS handler requires this. Without it, browser blocks initial POST to `/api/upload`. |
| 6 | **Unused local env vars** | LOW | `.env` has `VITE_AWS_REGION` and `VITE_AWS_S3_BUCKET` but frontend never uses them. Backend uses `AWS_REGION` and `AWS_S3_BUCKET`. |

## Implementation Plan

### Task 1: Fix Vercel Deployment — Serve Correct index.html
**CRITICAL — This is currently breaking the entire app.**

**File:** `vercel.json`

Add `"outputDirectory": "dist"` to tell Vercel to serve from the Vite build output:

```json
{
  "outputDirectory": "dist",
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ],
  "headers": [...]
}
```

**Why:** The root `index.html` references `/src/main.tsx` (Vite dev server). The production bundle is in `dist/index.html` and references `/assets/index-*.js`. Without `outputDirectory`, Vercel's SPA rewrite matches the root `index.html` instead of the built one.

**After fix:** Redeploy on Vercel. The page should render React instead of empty `<div id="root"></div>`.

### Task 2: Verify S3 CORS
User's CORS configuration looks correct:
```json
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET", "PUT", "HEAD"],
    "AllowedOrigins": [
      "http://localhost:5173",
      "https://e-commerce-mauve-one-98.vercel.app"
    ],
    "ExposeHeaders": ["ETag"]
  }
]
```

**Action:** After Task 1 is fixed, test upload and check browser DevTools → Network for CORS errors. If PUT to S3 fails with CORS, ensure `POST` is also in `AllowedMethods` (the backend `/api/upload` uses POST, though the S3 PUT itself only needs PUT).

### Task 3: Configure S3 Public Read Access
**Option A (Recommended for simplicity):**
- Disable "Block Public Access" on the bucket
- Add bucket policy allowing public read:
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::ecommerce-project5-rechimonth/*"
    }
  ]
}
```

**Option B (More secure):**
- Keep Block Public Access enabled
- Modify backend to return pre-signed GET URLs instead of public URLs
- Update frontend to use pre-signed GET URLs for display

**Recommendation:** Use Option A for now since the current architecture assumes public URLs.

### Task 4: Verify IAM Permissions
Your AWS user/role needs at minimum:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:PutObjectAcl"],
      "Resource": "arn:aws:s3:::ecommerce-project5-rechimonth/*"
    }
  ]
}
```
